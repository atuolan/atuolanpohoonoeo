## 1. 視訊通話不讀上下文，感覺很割裂　✅ 已修

**反饋**：視頻連接的時候不讀上下文嗎？感覺好割裂。

**原因**：`src/stores/phoneCall.ts`

- 語音通話 `startCall()`（約 709 行）會呼叫 `loadSummariesAndEvents(info)`，載入總結、重要事件、最近 15 則聊天
- 視訊通話 `startVideoCall()`（約 630 行）**完全沒有呼叫它**，整個專案也沒有別的地方幫它補
- 更糟的是 `cleanup()` 不會清掉這三份資料（`summaries`、`importantEvents`、`recentChatHistory` 只在 `loadSummariesAndEvents` 裡被寫入）。所以視訊時 AI 拿到的是：
  - 開 App 後第一次打就是視訊 → **什麼都沒有**
  - 之前打過語音 → **上一通語音的資料**，如果上一通是打給別的角色，就會**讀到別的角色的總結和聊天**

**修法**：
- 在 `startVideoCall()` 裡、`loadTTSConfig` 前面補上 `await loadSummariesAndEvents(info)`
- `cleanup()` 順便把這三份資料清空，避免以後又讀到上一通的
- 加測試：視訊和語音拿到的上下文一樣；連打兩個不同角色不會串

## 2. 通話的總結數量寫死 5 條　✅ 已修

`phoneCall.ts` 約 1492 行：`selectSummariesForPrompt(..., 5)`。
聊天、主動訊息都會照這個聊天的「總結讀取」設定（`resolveSummaryReadCount`），只有通話寫死 5。設成「全部」或 10 條的人，打電話時還是只讀 5 條。

**修法**：改成讀 chat 的 `summarySettings`，跟聊天一樣用 `resolveSummaryReadCount`。

## 3. 總結少了一節（兩人怎麼認識的不見了）　🟡 兩個可能

**反饋**（Doce，11/2）：重新玩梁sir，總結少了一開始兩人怎麼認識的部分；向量的重要事件裡倒是還在。

**可能 A：太舊被擠出去（照設計運作，但玩家不知道）**　✅ 確認是這個，已修：最早的一條一定送

**可能 B：合併總結把「釘選」弄丟了　🔴 確認是 bug**
- `src/composables/useChatSummaryDiary.ts` 約 1552 行：合併出來的元總結**一律 `isImportant: false`**
- 如果被合併的總結裡有一條是釘選的（例如「怎麼認識」），合併後原總結被收起來，元總結又沒有釘選 → 這段記憶就失去「永遠送」的保障，也會被擠出去
- 程式註解寫「要不要永遠記得由使用者決定」，但使用者當初已經決定過了（釘選了）

1. 是 AI 不記得，還是總結列表裡也看不到？
2. 那條總結當初有沒有釘選？有沒有做過「合併總結」？

**修法**（✅ 前兩項已做，`claude/plan-bug-fixes`）：
- 合併時，只要來源裡有任何一條釘選，元總結就自動釘選
- 元總結的提示詞加一句「開頭的初識經過、重要轉折必須保留」
- 考慮讓第一條總結預設釘選

## 4. 手動總結對 user 用「你」，自動總結用第三人稱　🟡 原因找到

**反饋**（Doce）：手動總結的，對 user 總是第二人稱；自動總結的，對 user 是第三人稱。

**原因**：
- 手動總結和自動總結都走同一個 `generateSummary()`，提示詞一樣
- 預設總結提示詞（`src/data/defaultPrompts/summary.ts` 約 117 行）寫「根據 {{user}} 的性別信息使用正確的代詞（他/她/Ta）」→ **第三人稱**
- 合併元總結的提示詞（`useChatSummaryDiary.ts` 約 1485 行）寫死「使用『你』代指 user，不要使用第三人稱」→ **第二人稱**
- 而且元總結存的是 `isManual: false`，但它是使用者手動按的

所以 Doce 說的「手動」幾乎可以確定是**合併出來的總結**。合併過的總結和一般總結混在一起，一下「他」一下「你」，所以覺得怪。

**修法**（✅ 已做：元總結改成跟一般總結一樣，角色「我」、user 用名字或他／她／Ta）：統一。建議元總結改成跟一般總結一樣，或是在總結設定裡加一個「怎麼稱呼 user：你／名字」，兩邊都照它。

## 5. 群組拉其他 user 進去　🟡 找到幾個問題

**目前的做法**：群組可以加「使用者角色·代演」成員（`isPersonaMember`），由 AI 代演。提示詞（`PromptBuilder.ts` 約 3190 行）有告訴 AI「這些是使用者角色，由你代演」，這部分沒問題。

**找到的問題**：

- 🟡 **可以把「自己」加成代演成員**：選單（`src/composables/useSubCharSources.ts` 約 114 行）列出全部人設，沒排除你在這個群正在用的人設。加進去後 AI 會代替你本人說話。
  → 修法：選單排除目前的人設，或加上提示。✅ 已做：選單排除目前的人設
- 🟡 **群聊總結分不清誰是 user**：`buildGroupSummaryPrompts`（`useChatSummaryDiary.ts` 約 290 行）給 AI 的成員名單混著角色和代演的 user，沒標明；真正的使用者本人也不在名單裡。AI 可能選代演的 user 當「主筆」，或把兩個 user 搞混。
  → 修法：名單標出「（使用者角色，AI 代演）」和「（真實使用者）」，並規定主筆只能選 AI 角色。✅ 已做
- ⚪ **圓桌會讓代演的 user 也輪流發言**（`ChatScreen.vue` 約 5295 行 `getRoundTableSpeakers` 沒有過濾）。可能是故意的，要確認你想不想要。

**還要實際測**：重要事件、行事曆的「指定角色」、記憶互通（`linkedMemory.ts` 已經排除代演成員，這個是對的）。
