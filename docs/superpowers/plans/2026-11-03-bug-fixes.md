# 計畫表：要修的問題（玩家反饋）

> 狀態：只查了原因，還沒修。

## 1. 視訊通話不讀上下文，感覺很割裂　🔴 已確認原因

**反饋**：視頻連接的時候不讀上下文嗎？感覺好割裂。

**原因**：`src/stores/phoneCall.ts`

- 語音通話 `startCall()`（約 709 行）會呼叫 `loadSummariesAndEvents(info)`，載入總結、重要事件、最近 15 則聊天
- 視訊通話 `startVideoCall()`（約 630 行）**完全沒有呼叫它**，所以視訊時 AI 看不到總結、重要事件和剛剛聊的內容
- `cleanup()` 還可能把上一通的資料清掉，所以視訊拿到的是空的

**修法**：在 `startVideoCall()` 裡、`loadTTSConfig` 前面補上 `await loadSummariesAndEvents(info)`。順便加測試，確認視訊和語音拿到的上下文一樣。

## 2. 總結少了一節（兩人怎麼認識的不見了）　🟡 很可能的原因

**反饋**（Doce，11/2）：重新玩梁sir，總結少了一開始兩人怎麼認識的部分；向量的重要事件裡倒是還在。

**很可能的原因**：`src/utils/summarySelection.ts` 的 `selectSummariesForPrompt`

- 預設只送**最新的 N 條**總結（預設 5 條），再加上標為「重要」的
- 最早那條「怎麼認識」的總結，時間最舊，聊久了就被擠出去
- 向量記憶是另外搜尋的，所以那邊還找得到

**還要確認**：她說的「少了」是 AI 不記得，還是總結列表裡**真的不見了**？如果列表裡也沒了，就要查元總結（合併）是不是把那段合併掉、又沒保留內容。

**修法方向**（擇一或都做）：
- 第一條總結（或「初識」類）預設自動標為重要，永遠送
- 總結面板顯示「這條目前沒有送給 AI」的標記，讓玩家知道要標重要或改讀取數量
- 元總結的提示詞強調「開頭的初識經過必須保留」

**順便發現**：通話裡的總結數量寫死 5 條（`phoneCall.ts` 約 1492 行），沒照這個聊天自己的「總結讀取」設定（`resolveSummaryReadCount`）。設成「全部」的人，通話時還是只讀 5 條。

## 3. 手動總結對 user 用「你」，自動總結用第三人稱　🟡 要再確認

**反饋**（Doce）：手動總結的，對 user 總是第二人稱；自動總結的，對 user 是第三人稱。

**目前查到的**：`src/composables/useChatSummaryDiary.ts`

- 手動總結（`handleTriggerManualSummary`）和自動總結（`triggerAutoSummary`）都走同一個 `generateSummary()`，提示詞一樣，照理不會不同
- **但是合併元總結的提示詞**（約 1485 行）寫死「使用『你』代指 user，不要使用第三人稱」
- 而一般總結的內建提示詞（約 1214 行）是「總結與 ${userName} 的對話」，AI 自然會用名字（第三人稱）

**很可能**：她說的「手動」其實是合併出來的元總結，或者提示詞管理裡的總結提示詞沒有規定怎麼稱呼 user，AI 每次自己決定。

**修法**：統一規則。建議一般總結、元總結、群聊總結都用同一種人稱（看大家習慣，「我」和「你」比較有代入感），或者在設定裡讓玩家自己選。

## 4. 群組拉其他 user 進去的功能　⚪ 還沒查

**反饋**：不確定有沒有問題。

**要做**：實際測一次流程。拉另一個 user（人設）進群後確認：
- 發言時 AI 分得清是哪個 user 在說話
- 總結、重要事件裡有沒有把兩個 user 搞混
- 圓桌發言順序、身份與工作有沒有包含新 user
- 行事曆的「指定哪些角色讀得到」有沒有影響

## 建議順序

1. 視訊通話上下文：原因明確，改一行加測試，最快
2. 通話總結數量照聊天設定：跟 1 一起改
3. 總結人稱統一
4. 初識總結被擠掉
5. 群組多 user 測試
