# 設計：他看得到你在手機上做什麼（看螢幕模式）

> 狀態：設計中，還沒開工。**第 0 步（可行性測試）要先過，才做後面的。**

## 想要的效果

玩家在聊天裡開啟「讓他看我的螢幕」，然後切去用別的 App（滑 IG、看影片、打遊戲）。
角色每隔幾分鐘看一次畫面，用**系統通知**回應（「你又在滑貓咪影片了？」）。
回到 App 時，這段期間他說的話都已經在聊天紀錄裡。

## 為什麼不用 MCP

MCP 是讓 AI 呼叫外部工具的規格，跟截圖無關。App 本來就自己呼叫 AI 的 API，
缺的是**原生的截圖能力**，這要 iOS 和 Android 各寫原生程式。

## 關鍵限制：背景時網頁不會跑

玩家切去別的 App 後，我們的 App 會進背景。iOS 幾秒內就會暫停 App，Android 的 WebView 也可能被暫停。
所以**截圖、送 AI、發通知都要在原生那邊完成**，不能靠網頁（Vue）。

整體流程：

1. 玩家在聊天裡按「讓他看我的螢幕」
2. 網頁準備好一份「看螢幕包」交給原生：
   - API 網址、金鑰、模型（要用看得懂圖片的模型）
   - 角色名稱、人設重點、最近的總結、最近幾則聊天（壓成一段系統提示）
   - 間隔（例如 3、5、10 分鐘）、每次最多回幾句
3. 原生開始截圖，每隔一段時間：
   - 縮小圖片（寬 720 左右、JPEG），控制費用和記憶體
   - 送去 AI，附上看螢幕包
   - 用角色的名字發系統通知
   - 把截圖時間和回覆存進佇列
4. 玩家回到 App，網頁讀佇列，把回覆插進聊天紀錄（標成「看螢幕時說的」）

## iOS：螢幕廣播擴充元件（ReplayKit Broadcast Upload Extension）

- 玩家從控制中心長按「螢幕錄影」→ 選「203 Phone」→ 開始廣播。上方會一直有紅色錄影標示（系統規定，拿不掉）
- 廣播期間，**擴充元件**（跟 App 分開的小程式）會一直收到畫面；它自己抽樣、送 AI、發通知
- 擴充元件記憶體上限很低（大約 50MB），所以每次只留一張縮小的圖，不能累積
- 擴充元件和 App 要共用資料（看螢幕包、回覆佇列），要用 **App Group**

### ⚠️ 風險：自簽安裝

目前 iOS 版是 GitHub Actions 打出**沒簽名的 IPA**，玩家用 **Sideloadly＋自己的 Apple ID** 簽名安裝。
以下幾點**不確定**，要實測：

1. Sideloadly 簽名時，會不會一起簽好擴充元件（`.appex`）
2. 免費 Apple ID 能不能用 App Group；如果不行，擴充元件和 App 拿不到同一份資料
3. 多一個擴充元件會多用一個 App ID，免費帳號 7 天內能建的 App ID 有限

如果 App Group 不能用，備案：擴充元件只做「截圖＋送 AI＋發通知」，看螢幕包在開始前透過別的方式傳過去（要再研究），回覆只出現在通知裡，不寫回聊天。

### 熱更新沒用

這是原生程式，**Capgo 熱更新送不過去**。玩家要重新下載 IPA、重新用 Sideloadly 安裝。

## Android：螢幕擷取（MediaProjection）＋前景服務

- 玩家按開始 → 系統跳出「要開始分享螢幕嗎？」→ 允許
- 開一個**前景服務**，通知列會一直顯示「正在讓 ○○ 看你的螢幕」（系統規定）
- 服務裡定時抓一張畫面 → 縮小 → 送 AI → 發通知 → 存佇列
- Android 14 以後每次開始都要重新允許，這是系統規定
- 一樣要重新裝 APK，熱更新送不過去

## 兩邊共用

- **網頁那邊**只做一份：準備看螢幕包、設定頁、讀佇列寫回聊天
- **Capacitor 外掛介面**兩邊一樣：`start(pack)`、`stop()`、`readQueue()`、`clearQueue()`
- **AI 請求格式**用 OpenAI 相容格式加圖片，原生兩邊各寫一次

## 費用和隱私

- 每張截圖都是一次看圖的 API 費用。設定頁要寫清楚，預設間隔 5 分鐘、可以調
- 加「單次最長時間」（例如 1 小時自動停），免得忘記關
- **暫停按鈕**放在通知上
- Android 可以設「這些 App 不截圖」（銀行、密碼管理）。iOS 擴充元件看不到現在是哪個 App，做不到，要在說明裡提醒
- 截圖只送給玩家自己設定的 API，不存檔、不上傳到別的地方

## 步驟

0. **可行性測試（iOS，最先做）**：做一個最小的廣播擴充元件，只做「每 30 秒發一則『我看到了』通知」。
   用 GitHub Actions 打包 → 你用 Sideloadly 安裝 → 確認：
   - 擴充元件有出現在「螢幕錄影」的選單裡
   - 開始廣播後有收到通知
   - App Group 能不能讀寫
   **這步過了才做下面的。** 我在雲端環境沒辦法編譯或執行 iOS，只能寫好程式交給 GitHub Actions 打包，要靠你在 iPhone 上測。
1. 網頁：看螢幕包、設定頁、佇列寫回聊天（兩邊共用，可以先寫好並測試）
2. iOS：擴充元件抽樣、縮圖、送 AI、發通知、寫佇列
3. Android：MediaProjection＋前景服務，做一樣的事
4. 加上暫停、自動停止、略過 App（Android）
5. 教學頁：怎麼從控制中心開始廣播（iOS）、權限說明（Android）
